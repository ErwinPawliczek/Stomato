# P1-05: Property validation harness — every package vs CoolProp / NIST reference set

- **Phase:** 1
- **Depends on:** P1-01
- **Packages you may edit:** `scripts/`, `data/validation/` (new), `tests/validation/` (new), `docs/validation.md` (new)
- **Contract change:** no
- **Benchmark delta expected:** none

## Goal
"Replace Aspen" is a credibility claim. Credibility comes from a published, reproducible table of
how every property package performs against reference data, per property, with tolerances we
chose *before* seeing the numbers. Today there is one golden thermo test. Build the harness that
turns the validation into a committed artefact and a CI gate.

## Files
- Create: `data/validation/cases.yaml` — the reference set. Each case: `id`, `package`
  (`pr|srk|pr78|nrtl|all`), `components`, `z`, `T`, `P` (or `T`+`vf`), `source`
  (`coolprop:<fluid>` for pure fluids via the reference Helmholtz EOS; `nist:<webbook id>`
  with the quoted value and retrieval date; `literature:<citation>` for binaries), `expected`
  (any of `vf, rho_V, rho_L, H, S, Cp, bubble_P, dew_P, K`), and `tolerance` per property.
  Minimum content:
  - Pure fluids (CoolProp): CH4, C2H6, C3H8, n-C4H10, CO2, H2S, N2, H2O — saturated
    density (V and L), Cp, bubble/dew P at 5 temperatures each spanning 0.5–0.95 Tr.
  - Binaries (literature VLE): C1/C3 (Reamer, Sage & Lacey 1950), CO2/C1 (Davalos et al.
    1976), C1/H2O (Culberson & McKetta 1951), ethanol/water for NRTL (Kurihara et al. 1993).
    Bubble P and y at ≥ 6 points each. Cite table and page.
  - Multicomponent: the slice inlet at 500 psia / 300 K against a GPSA K-value chart point
    (GPSA Engineering Data Book, Fig. 25-x; state the figure).
  Tolerances (fixed now): cubic EOS vs reference density 3 % vapour / 8 % liquid (known cubic
  weakness), Cp 5 %, bubble/dew P 3 %, K-values 5 %; NRTL ethanol/water bubble P 2 %, y 0.02 abs.
- Create: `scripts/validate_properties.py` — runs every case through the named package(s) via
  the contract (no library bypass), writes `data/validation/results.json` with
  `{case, property, expected, got, rel_err, pass}` plus environment metadata, and prints a table
  per package: n cases, pass rate, worst 5 misses with their sources.
- Create: `tests/validation/test_reference_cases.py` — parametrised over `cases.yaml`; each case
  is one test; failure message shows expected/got/source. Marked `validation` (register the
  marker is in locked `pyproject.toml`? — no: use `pytest.mark.validation` without registration
  warnings by declaring it in `tests/validation/conftest.py` via `pytest_configure`).
- Create: `docs/validation.md` — generated by the script (`--write-doc`): the table above, the
  tolerance policy, and how to add a case. Committed; regenerated in the P1-05 PR.
- `data/validation/` is **not** a locked oracle yet; after P1-05 merges the orchestrator adds it
  to the locked list.

## Method
Reference values are typed into `cases.yaml` by the implementer **from the source**, with the
retrieval date; the script never fetches. CoolProp values may be generated by a one-off helper
(`scripts/validate_properties.py --regen-coolprop`) that writes them with `source: coolprop`
and the CoolProp version — these are regenerated, not hand-typed. Literature values are
hand-typed and cited.

## Acceptance criteria
- [ ] ≥ 150 reference points across the cases above; every literature point cites table/page
- [ ] `uv run pytest tests/validation -rs` runs them all; failures (if any) are listed in the PR with the implementer's assessment (model limitation vs bug) — do **not** loosen a tolerance to pass
- [ ] `docs/validation.md` committed and matches `results.json`
- [ ] `scripts/validate_properties.py` uses only the `Thermo` protocol (grep: no `from thermo import` / `CoolProp` outside the regen helper)
- [ ] ruff, mypy, lint-imports, full `pytest -rs` green
- [ ] Nothing outside the listed paths changed
