# U-R2: Level-wave conventions (every R1/R2 unit thread follows this)

- **Phase:** Unit catalogue, levels beyond R0 for every row (docs/unit-catalogue-plan.md).
- **Depends on:** U-R1 (round-1 conventions, all of which still bind unless amended here), U-01d (#243, per-unit V1 case files).
- **Contract change:** no. A thread that needs one stops and posts `BLOCKED:` on its issue.
- **Plans:** one spec per unit row in `specs/backend/units/<unit_id>.md`. It gives the method, the exact equations, the params schema, the files and the steps. The thread implements that spec, and nothing outside it.

## Ownership: why threads cannot collide
Each unit thread owns exactly these paths, and no other thread touches them:
1. **New module(s)** named in its unit spec, for example `src/ngdesign/units/<family_pkg>/<unit_id>_r1.py`. The R0 module is NOT edited, even when it shares a file with another row (for example `heat_exchange.py`); the higher level imports from it read-only.
2. **Tests:** `tests/units/<family_pkg>/test_<unit_id>_r<k>.py` (new files only).
3. **V1 cases:** `data/validation_units/<family>/cases/<unit_id>.yaml` (U-01d per-unit file). Never the family `cases.yaml`.
4. **Catalogue:** inside `data/unit_models/<family>.yaml`, only the `levels.R<k>` entries of its own row, plus the row's `notes` line when recording a V1 gap. No other row and no other key.
5. **Generated docs:** regenerated by the harness, never hand-edited. `docs/units.md` conflicts on almost every merge; the orchestrator resolves it at merge time. If you hit it, take main's version and regenerate.

Shared libraries are called, never edited: `ngdesign.sizing.*`, `ngdesign.units._physics.*`, `ngdesign.units.balance`, the `fluids` and `ht` packages (MIT, runtime dependencies), and `Thermo` through its protocol only. If the unit spec says a correlation is missing from them, implement it privately in your own module with its citation. The orchestrator consolidates shared helpers later, so never add them to a shared module yourself.

## Level semantics
- Each new level is a new adapter class registered through the catalogue YAML: `levels.R<k>.adapter`, `status: provisional`, `params` as a JSON schema, `note`, and `validation` ids.
- The higher level must **reduce to the lower level** in a limit stated in the unit spec (for example, a flat pump curve at the R0 efficiency gives R0's outlet exactly). The identity test asserts it to 1e-10 relative, or to the stated round-off.
- A level whose method needs geometry or a curve takes it as params, with documented units and no hidden defaults beyond those listed in the spec's params table.
- Every level closes V0 at 1e-8 under the U-R1 energy rule. A sizing or rating quantity that does not enter the balances is reported in `info` with its unit in the key name (`dP_Pa`, `U_W_m2K`).

## Validation
- **V1:** printed inputs and printed results only, from a cited source with its page, example or equation number. No input echoes, and no model outputs used as expected values. The tolerance is the source's rounding; a miss goes in `assessed` with the measured number and the cause. Case ids match `V\d+-...`.
- If the unit spec's candidate sources are not accessible, ship the level `provisional` with the V1 gap recorded in the row `notes`, naming what was searched. **Never invent or reconstruct a number.**
- At least one **closed-form test** per level, hand-computed in the test docstring from the spec's equations, plus the identity test.
- Every refusal is a typed `ValueError` subclass naming the parameter, reached by a test with `pytest.raises(OneError, match=...)`.

## Time box and survival (implementer threads are cut off after about an hour)
- **First action, within 5 minutes:** comment on your issue that you have started, with the origin/main head.
- **Branch:** `u-lv/<unit_id>` from origin/main; push within 15 minutes.
- **Open the PR right after your first push**, titled `<unit_id> R<k>: <method>`, with `Closes #<issue>`, and keep it updated; it is the record if you are cut off.
- Work the unit spec's numbered steps in order. After each one: run its tests, commit, push, and comment `step N done <SHA>` on the PR with measured numbers.
- A follow-up thread continues from the branch and the PR comments. Never force-push.
- Run every local python/pytest/script command under `timeout 900`. No full local suite.

## Gates
`uv run ruff check .`, `uv run ruff format --check .`, `uv run mypy src tests` (strict), `uv run lint-imports`, `uv run python scripts/bench_baseline.py --check`, then `uv run python scripts/validate_units.py` and `--audit` as separate commands. Targeted pytest only: your test files, `tests/units/test_unit_catalogue.py` and `tests/property/test_unit_balances.py`. GitHub CI green on the final head. Do not merge.
